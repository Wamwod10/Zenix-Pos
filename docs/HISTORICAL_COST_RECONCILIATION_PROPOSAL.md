# Historical cost reconciliation proposal ? no production changes

Status: proposal only. Existing transfer and sale snapshots can be zero either legitimately or because cost was lost; current catalog prices cannot reliably reconstruct them. Do not automatically backfill, overwrite balances, or alter financial history.

First approve accounting policies for dispatch cost, weighted-average receipt, differences and partial receipts, negative/zero stock, precision, cancellation and returns at original versus current cost. Example: source 10 at 20, destination 10 at 5, transfer 5: dispatch-cost weighted average would be (10?5+5?20)/15=10, instead of current 5. Confirm treatment of in-transit stock, variance and ledger postings before implementing. Snapshot source cost transactionally at dispatch; receive from that immutable snapshot with scoped row locks, idempotency and concurrency tests. This is a candidate policy, not an approved implementation.

Read-only diagnostic: scope by organization, product and branch; correlate receipts, dispatches, transfer lines and movements, return/sale snapshots and inventory balances in timestamp and transaction order. Flag missing provenance separately from documented zero-cost items. Report confidence, affected periods, inventory/COGS/profit impact and required source documents; never infer historical values from today's reference price. Reconcile against independent accounting records and obtain owner/accountant approval. Only after review design auditable adjustment entries, approval controls, backup and rollback, and test in a disposable database. Production correction requires separate explicit authorization.
